FastAPI / Excel Automation — Working Prototype

Valora

Construction valuation, progress-payment certification, and reporting — governed around the Excel documents engineers already use.

Project type

Independent working prototype, in active development

Role

Product concept, workflow design, system architecture, development

Primary users

Project coordinators, technical-office engineers, site managers, commercial teams

Development status

Local working prototype — not yet a production platform

Core technologies

FastAPI, Python, SQLite, openpyxl, Jinja2, JavaScript, Leaflet.js, LibreOffice, Poppler

01

Overview

Valora is a construction-management prototype for periodic progress-payment certification — known as hakediş in Turkish practice. It manages the relationship between Bills of Quantities, completed work, cumulative progress, financial deductions, and formally structured Excel documents across payment periods.

Rather than replacing Excel, Valora places a controlled web application around it: generating, versioning, validating, and archiving protected workbooks while keeping the working environment engineers already know.

02

The problem

Contractors are typically paid through periodic valuations based on completed quantities — each period involving measured quantities against a Bill of Quantities, cumulative calculations, advance and retention deductions, VAT withholding, and formally structured approval documents. These workflows are usually managed through manually edited Excel files, which creates:

  • inconsistent file structures between engineers and projects
  • vulnerable formulas and unprotected cells
  • manual, error-prone transfer of cumulative quantities between periods
  • files overwritten between periods, with unclear version history
  • limited control over who can edit or delete records

A single typing or formula error can propagate through an entire chain of dependent financial calculations.

03

Design challenge

How can a construction organisation introduce standardisation, traceability, and version control without forcing engineers to abandon familiar Excel-based workflows?

A completely new interface risks resistance and demands real behavioural change; leaving everything in Excel keeps familiarity but sacrifices governance. Valora's answer is a transitional strategy: keep Excel as the working document, but move generation, validation, history, and control into a central system around it.

04

Core workflow

Create project ↓ Define contract and project metadata ↓ Import or define Bill of Quantities ↓ Create payment period ↓ Generate protected Excel workbook ↓ Engineer records current-period quantities ↓ Validate and archive completed workbook ↓ Generate client-facing PDF document set ↓ Start the next payment period, carrying forward cumulative quantities

Each period is a separate historical record — the next period is created from the completed previous one rather than overwriting it.

05

Key capabilities

Structured workbook generation

Valora programmatically generates a protected, formula-driven workbook per project and period — nine interconnected sheets, roughly 1,000 lines of generation logic, controlling formulas, cell protection, print areas, and metadata.

Period rollover

When a new period begins, Valora reads the completed previous workbook and carries cumulative quantities forward automatically (new previous quantity = previous period's previous + current), while the old period stays archived and unchanged — removing manual reconciliation between files.

Naming, versioning, and role-based access

Structured project/period codes are generated from configurable metadata; the system asks for explicit confirmation rather than silently renaming or overwriting records on conflict. Administrators, coordinators, site managers, and viewers each get different permissions — treated as organisational governance expressed through software, not just an access-control feature.

One-click PDF export and daily site reporting

The complete workbook converts to a print-ready, client-facing PDF set via headless LibreOffice and Poppler. A separate daily-report module standardises subcontractor, production, material, equipment, and labour reporting that would otherwise scatter across WhatsApp and paper.

06

Architecture

FastAPI web application | |-- Project and contract management |-- Payment-period lifecycle |-- User roles and permissions |-- Daily site reporting / cost analysis | |-- SQLite database | |-- openpyxl workbook generator | `-- Protected nine-sheet Excel workbook | `-- Document pipeline |-- LibreOffice headless `-- Poppler PDF processing

07

Key design decisions

  • Preserve familiar tools — engineers keep working in Excel; Valora controls how the workbook is generated, stored, and carried between periods.
  • History instead of overwrite — every period is a separate record; auditability is prioritised over the convenience of one endlessly-edited file.
  • Governance through system rules — role restrictions, locked formulas, and naming conventions define who can change what, and when.
  • Incremental digital transition — the bet is that stronger adoption comes from wrapping control and integration around existing routines, not replacing them outright.

08

Current status and limitations

Working prototype — actively developed

Valora runs locally as a working prototype and has not been deployed as a production platform.

  • SQLite rather than a production-scale database; no formal security audit or load testing
  • no integration with accounting or ERP platforms
  • no formal usability study; no validation across different contract standards
  • reliance on LibreOffice for document conversion
  • financial formulas require project- and contract-specific verification before professional use

09

Reflection

Valora began as a technical attempt to improve progress-payment documents; the deeper issue turned out to be organisational — who owns the process, how standards are maintained, which familiar routines should be preserved, and when incremental integration beats wholesale replacement.

Software functionality does not automatically become organisational capability. A technically complete system can still fail to create value if users reject its workflow, management doesn't support implementation, or project-specific routines conflict with corporate standards.

Valora is both a working prototype and an ongoing exploration of how construction organisations might move from fragmented files toward structured, governed digital processes.
